# Лиса 4.1.14 — новая иконка с фотографией лисы

Эта версия предназначена для автоматического перехода со старого сервера
`192.168.0.199:8000` на новый сервер `192.168.10.75` через доступный порт 80.

После установки клиент сам заменяет старый адрес даже в ранее сохранённом
файле `%USERPROFILE%\.lisa_client\settings.json`. Пользователю не нужно менять
поле сервера вручную.

Файл `1.ico` с новой фотографией лисы встраивается в `Lisa.exe` и
`Updater.exe`, используется окном программы и отдельным идентификатором
приложения на панели задач Windows. Эта же фотография показана в шапке
основного окна «Лисы».

Исправлено чтение большого XLSX из Sigur, в котором служебная граница листа ошибочно указана как `A1`, хотя внутри находятся десятки тысяч строк.

Клиент теперь:

- принудительно пересчитывает границы листа перед чтением;
- понимает двухстрочную шапку Sigur, где «Таб. №» и «ФИО» находятся под заголовком «Объект»;
- отбрасывает взломы, запрещённые и незавершённые попытки прохода;
- проверяет все листы книги, а не только активный;
- автоматически находит строку заголовков;
- распознаёт столбцы по названиям, даже если они переставлены;
- поддерживает общий столбец «Дата и время»;
- определяет вход и выход по направлению, событию или названию считывателя;
- сохраняет последний полученный файл в `%LOCALAPPDATA%\Lisa\last_server_report.xlsx`.

## Сборка на Windows

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_client.ps1
```

После сборки:

- `outputs\client_to_users` — файлы для первоначальной установки;
- `outputs\update_to_server` — файлы, которые нужно скопировать в `C:\AristocratServer\updates` для автообновления всех клиентов.

## Схема перехода

Старая версия `4.1.12` ищет манифест по адресу
`http://192.168.0.199:8000/updates/version.json`. Старый сервер нужно оставить
включённым на время перехода: он раздаёт установочный пакет `4.1.14`.

На новом сервере уже настроено перенаправление порта 80 на локальный порт 8000.
После обновления клиент обращается к API по адресу `http://192.168.10.75`.

После сборки скопируй `outputs\update_to_server\Лиса.exe` и `version.json` в
`C:\AristocratServer\updates` с заменой. В переходном манифесте ссылка на
скачивание намеренно использует старый IP: так версия `4.1.12` сможет скачать
новый EXE. После запуска `4.1.14` сохранённый API автоматически станет
`http://192.168.10.75`.

Чтобы опубликовать готовую сборку одной командой на серверном ПК, выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\publish_transition_update.ps1
```

Скрипт проверит версию и SHA-256 перед копированием.

Проверка перед публикацией со старого сервера:

```powershell
Invoke-RestMethod http://192.168.10.75/ping -TimeoutSec 10
```

Если отображается версия сервера `1.2.10`, переход доступен. Рядом со старой
`Лиса.exe` у пользователей должен находиться `Updater.exe`.
