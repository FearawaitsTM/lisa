# ServerLisa 1.2.24 — рабочие столы Windows и время

На втором виртуальном рабочем столе Lisa видела ошибку «Не удалось найти
соседние поля «От» и «До»»: Sigur находился на другом столе, а снимок
экрана показывал только Lisa. Теперь сервер ищет видимые поля на соседних
рабочих столах через Ctrl+Win+стрелки, выполняет запрос на столе с Sigur
и затем возвращается на исходный. Поиск ограничен шестью столами влево
и двенадцатью шагами вправо. Если Sigur не виден, отчёт не запускается.

Проверка времени больше не зависит от картинки `time_zero_anchor.png`:
сервер считывает значение времени рядом с каждой найденной датой и требует
`00:00` в обеих строках. На двух присланных видах Sigur этот способ прочитал
оба поля как `00:00`. Работа переключения виртуальных столов и весь путь
до готового Excel на вашем Windows требуют пробного запроса.

На снимке от 21 октября обе даты уже введены: «От» 19.08.2026 00:00,
«До» 20.10.2026 00:00. Запрос клиента заканчивается 19.10.2026
включительно, поэтому в Sigur конец периода ставится на следующие сутки.
Сервер останавливался потому, что старые шаблоны не узнавали кнопку.
Для текущего и прежнего масштаба Sigur добавлены отдельные шаблоны её надписи.
Кнопка ищется только в области под полями дат, затем нажимается по центру
надписи. Если она не найдена, сохраняется `debug_report_button_not_found.png`.
Пробный запуск на вашем компьютере всё ещё нужен для проверки Excel-файла.

На снимке после 1.2.21 сервер остановился до кнопки «Получить отчёт»:
распознавание прочитало дату «До» как `20.10.,2026`. Лишняя запятая
считается ошибкой OCR, если три группы цифр точно совпадают с нужными
днём, месяцем и годом и Sigur не показывает красную рамку. Слипшиеся
или неверные числа по-прежнему останавливают отчёт.

## Период отчёта

Дата «До» клиента считается включительно. Для запроса 19.10.2026–19.10.2026
сервер ставит в Sigur «От» 19.10.2026 00:00 и «До» 20.10.2026 00:00.
Прибавление календарного дня правильно переходит через конец месяца и года.
Поля времени сервер не меняет, только убеждается, что обе строки показывают
00:00; на присланном снимке это так. Если время уже не 00:00, отчёт
останавливается с указанием поля, чтобы не отдать неверный период.

На последнем снимке дата «До» визуально верна, но сервер отверг её из-за
порога уверенности распознавания 0,85. Порог снижен до 0,70 при сохранении
точного сравнения всех символов и проверки красной рамки.

Перед вводом неверная дата целиком выделяется мышью и удаляется. Проверка
учитывает как чёрный, так и красный текст; при остатке очистка повторяется.
После записи точный текст даты и красная рамка проверяются на снимке.
Работу полного запроса на вашем компьютере нужно подтвердить пробным отчётом.

Sigur не отдаёт поля даты через доступность Windows: версия 1.2.15 видела
только всё окно и останавливала отчёт. Теперь сервер читает именно текст
каждого поля со снимка экрана. На присланном исходном снимке распознавание
вернуло `19.08.2026` и `19.10.2026`; на снимке с красными полями оно прочитало
обе слипшиеся строки, поэтому они будут отклонены.

Если в поле уже нужная дата и нет красной рамки, сервер её не переписывает.
В остальных случаях он сначала выделяет и удаляет старое значение и убеждается,
что поле пусто, и только затем печатает дату с точками. Отчёт запускается
лишь при точном совпадении считанного текста с запросом и отсутствии красной
рамки. Ввод на вашем экземпляре Sigur ещё нужно проверить пробным запросом.

После создания отчёта Sigur открывает временную книгу Excel `tc-tmp...` и
иногда показывает диалог с кнопкой «ОК». Сервер ждёт именно новый файл,
подтверждает только окно процесса Excel и закрывает только эту временную книгу.
Ветку сохранения через Edge и нажатие Enter наугад из обработки отчёта убрали.

Добавлен `install_server.ps1`: он собирает EXE, останавливает старый процесс,
заменяет файлы в `C:\AristocratServer`, отключает найденные старые способы
автозапуска ServerLisa и регистрирует задачу запуска текущего EXE при входе
пользователя в Windows. После установки запускает сервер и проверяет версию
через `/ping`. Папки `data` и `updates` сохраняются. Отключённые записи
автозапуска перечислены в `autostart_backup_*.json` рядом с EXE.

При неудаче сервер сохраняет `debug_date_entry*.png` в `data/reports` и не
нажимает «Получить отчёт». После обеих успешных проверок сохраняется
`debug_dates_entered.png`.

Добавлена поддержка нового способа выгрузки Sigur: программа может сразу
открывать книгу Excel `tc-tmp...` из `%LOCALAPPDATA%\Temp` без обычного
расширения файла. Сервер проверяет внутреннюю структуру книги, автоматически
забирает готовый временный файл и отправляет клиенту как `sigur_report.xlsx`.
Нажимать «Сохранить» или «Сохранить как» вручную не требуется.

После чтения сервер закрывает без сохранения только созданную Sigur книгу
`tc-tmp...`. Остальные открытые книги Excel не затрагиваются, а следующий
запрос отчёта можно выполнять без ручного закрытия окна.

Если дата не подтверждена, сервер возвращает ошибку вместо отчёта.

Это проект, восстановленный из присланного рабочего `ServerLisa.exe`. В нём сохранены маршруты:

- `/report`
- `/ping`
- `/shift-schedules`
- `/night-employees` (совместимость со старыми клиентами)
- `/updates/version.json`
- `/updates/{file_name}`

## Что ускорено

- Убраны все вызовы `time.sleep` из обработки отчёта.
- Убраны обязательные паузы по 1–3 секунды после каждого действия.
- Окно Sigur и файлы проверяются адаптивно: переход выполняется сразу после готовности.
- Проверка готовности выгруженного файла сокращена с 2 секунд до 0,25 секунды.
- Шаблоны кнопок OpenCV подготавливаются один раз и используются повторно.
- Возвращены изображения полей `date_from.png`, `date_to.png` и старой кнопки `get_report.png`.
- Поля дат сначала ищутся по картинкам; координаты используются только как запасной вариант.
- Кнопка отчёта ищется по двум масштабам надписи и двум старым шаблонам внутри области под полями дат.
- Захват экрана выполняется напрямую через `PIL.ImageGrab`; зависимости Pillow и PyScreeze принудительно включаются в EXE.
- Поиск изображений дат ограничен областями настоящих полей; ложные совпадения в других частях Sigur отклоняются.
- Сервер ищет новые отдельные шаблоны подписей `От:` и `До:` из текущего интерфейса Sigur, а не старые похожие пустые поля.
- Полная дата проверяется распознаванием текста на экране; поле времени не затрагивается.
- Сервер сравнивает обе даты с запросом и проверяет отсутствие красной рамки.
- Если Sigur не принял дату, отчёт не запускается и пустой файл клиенту не отправляется.
- Конечная дата клиента включительна; в Sigur устанавливается полночь следующего дня.
- Обрабатывается временный отчёт Excel и его диалог «ОК».
- SQLite работает в режиме WAL, добавлен индекс периодов смен.

## Как исключены старые данные

Перед нажатием «Получить отчёт» сервер запоминает точный список и состояние файлов во всех папках поиска. После нажатия принимается только новый файл либо файл, который действительно изменился. Старые `.xlsx` и `.csv` больше не могут быть возвращены как результат нового запроса.

База ночников и смен не удаляется: существующие настройки сотрудников сохраняются.

## Сборка на Windows

Файл `1.ico` с новой фотографией лисы уже включён в проект. Скрипт сборки встраивает его в
`ServerLisa.exe`, поэтому значок отображается у EXE, в заголовке консольного
окна и на панели задач Windows.

Распакуй архив, открой PowerShell **от имени администратора** в папке проекта
и выполни одну команду:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install_server.ps1
```

Скрипт создаст файлы здесь:

```text
outputs\server_to_install
```

Скрипт сам остановит старый сервер и скопирует готовые файлы в
`C:\AristocratServer`. После перезагрузки сервер запускается при входе в
Windows под тем пользователем, который выполнил установку. Для работы с
окнами Sigur и Excel пользователь должен войти в Windows.

Проверка после запуска:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/ping | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8000/shift-schedules | ConvertTo-Json -Depth 5
```

В `/ping` должна быть версия `1.2.22`.
